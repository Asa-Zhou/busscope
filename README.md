# BusScope

桌面端串口调试工具，用来观察 Modbus RTU 通信；CAN 规划在 V2。
技术栈：**Qt 5.14.2 + C++17 + qmake + MinGW 7.3 64-bit**。

## 当前状态（P2，可编译可运行）

已实现：

| 模块 | 说明 |
|---|---|
| 串口连接 | 端口枚举 / 刷新、波特率、帧格式（8-N-1 等），打开-断开状态可视化 |
| Modbus RTU 收发 | 主站请求 + 响应，自动 CRC16（小端序） |
| 帧切分 | 按功能码推导期望长度，支持异常响应（5 字节）与多寄存器响应 |
| 帧解码 | 01/02/03/04/05/06/0F/10，PDU 地址映射成 0xxxx/1xxxx/3xxxx/4xxxx 点表编号 |
| 异常识别 | 异常响应（红）、CRC 校验失败（琥珀）、响应超时（琥珀）三种状态分色 |
| 帧详情 | 字段表 + 原始字节 + 请求→响应耗时 |
| 发送 | HEX / ASCII、自动 CRC、Ctrl+Enter、周期发送（20 ms ~ 60 s） |
| **点表轮询** | 每行一条读任务，独立周期/超时/重试；串行调度保证半双工不冲突 |
| **数值解释** | bool / int16 / uint16 / int32 / uint32 / float + 系数 + 单位 |
| **点表导入导出** | 点「导出点表」直接弹格式菜单（CSV / TXT）；导入自动识别 Tab、逗号、分号、空白分隔 |
| **写寄存器** | 双击点表任意行 → FC06 写单寄存器（轮询中自动插队） |
| **CAN 收发** | 创芯/兼容 ZLG 的 USB-CAN（ControlCAN.dll），收帧列表 + 发送（ID/扩展帧/远程帧/数据） |
| **示波器** | 嵌入在点表页下方，也可弹出为独立窗口；**右键点表任意一行 → 添加到示波器**（最多 4 条曲线），多通道各自归一化并带图例；单通道显示 Y 轴刻度与 min/max/avg，每通道保留 600 点 |
| **串口热刷新** | 左栏串口行右侧的图标按钮，或 `Ctrl+R` |
| 其他 | 常用指令、CSV/TXT 导出（带 BOM）、清空、自动滚动 |

未实现：CAN DBC 解码、报文过滤、无边框自绘标题栏。

## 启动行为（打开就有数据）

程序会记住上次的连接方式，下次启动自动恢复：

| 记住什么 | 存在哪 | 行为 |
|---|---|---|
| 串口 + 波特率 | `HKCU\Software\BusScope\BusScope\conn` | 启动时自动打开；端口不存在就退回默认选择 |
| 上次的点表文件 | `...\poll\lastFile` | 启动时自动载入，并切到 Poll 页 |
| 自动轮询 | 有任务就开 | 串口连上后直接开始轮询，不用再点「开始轮询」 |

所以日常用法就是**从 Release 下载解压后双击 `BusScope.exe`**，几秒后点表就在跑。

想临时换个口：左边「断开串口」→ 选新端口 → 打开。

## 界面结构

```
┌──────┬──────────────────────────────────────┐
│Modbus│  [Slave · 收发]  [Poll · 轮询]        │
│      ├──────────────────────────────────────┤
│ CAN  │  连接配置 │ 帧列表 │ 发送             │
└──────┴──────────────────────────────────────┘
```

- **左侧竖栏选协议**：`Modbus` / `CAN`，选中项图标变亮、左侧有蓝色竖条
- 选 Modbus 时，顶部出现二级页签：
  - **Slave · 收发**：串口连接 + 帧列表 + 帧详情 + 手动发送（原来的一整套）
  - **Poll · 轮询**：点表 + 示波器
- 选 CAN 时直接进 CAN 页，没有二级页签

## 示波器怎么用

三种入口，同一份数据：

| 入口 | 位置 |
|---|---|
| 右键菜单 | 点表任意一行 → 添加到示波器 / 从示波器移除 / 清空 / 打开独立窗口 / 存图 / 导出数据 |
| 工具栏 | 点表页顶部「示波器」按钮，切换独立窗口显示 |
| 波形区右上角 | 「暂停」「各自归一 / 统一刻度」「导出」「独立窗口」 |

规则：

- 最多 **4 条曲线**，**点左侧列表的勾选框可以临时隐藏某条**（不看但不删）
- **单通道**：Y 轴显示真实刻度 + min/max + 当前值
- **多通道**：默认「各自归一」（每条按自己值域铺满，只看形状）；
  点「统一刻度」改成共用一个 Y 轴，看真实数值——量纲差太大时曲线会被压平，那时候还是用归一化
- 底部显示 **`xx s/div` 和跨度**，配合点状网格判断采样是否连续、有没有断档
- **暂停**：画面冻结（数据仍在后台累积），恢复后直接跳到最新
- 独立窗口和嵌入区共用同一份通道列表，数据同步刷新
- 每个通道保留 **5000 个采样点**（500 ms 周期约 40 分钟），回看粒度够一段完整工况

### 缩放 / 回看

| 操作 | 效果 |
|---|---|
| **滚轮**（绘图区内） | 以鼠标位置为锚点缩放；上滚放大、下滚缩小，最小到 200 ms |
| **左键拖动**绘图区 | 平移视窗，往右拖看更早的数据 |
| **拖底部滑块** | 快速跳到历史某一段；滑块宽度就是当前视窗占比 |
| **双击绘图区** | 回到最新，并把视窗恢复成「全部历史」 |
| **「回到最新」按钮** | 同上；跟随时按钮显示「● 实时」并置灰 |

进入回看后：

- 波形右上角出现 **`◀ 回看中`**
- 标题行右侧停止刷新当前值，底部显示 **`15:58:28 → 16:00:13`** 的时间范围（琥珀色）
- 新数据继续累积，不会把画面拽走；点「回到最新」或双击即可追上

### 波形导出

波形区右上角「导出」，或独立窗口里点同一个按钮：

| 选项 | 说明 |
|---|---|
| 保存为图片 (PNG) | 直接截当前波形区；独立窗口开着时截窗口里那张（更大） |
| 导出数据 (CSV) | 长表格式：`时间,通道,数值,单位`，每行一个采样点 |
| 导出数据 (TXT) | 同上，Tab 分隔 |

时间列是 `HH:mm:ss.zzz`，多个通道按各自采样时刻混排，Excel 里做透视就能画自己的图。

## 点表文件格式

`examples/points-sample.csv` 可以直接改：

```
名称,从站,功能码,地址,数量,周期ms,超时ms,重试,类型,系数,单位
母线电压,1,3,0,1,500,200,1,uint16,0.1,V
母线电流,1,3,1,1,500,200,1,int16,0.1,A
累计充电量,1,3,4,2,2000,300,1,uint32,0.1,kWh
```

- 功能码：`1` 线圈 / `2` 离散输入 / `3` 保持寄存器 / `4` 输入寄存器
- 数量：读几个寄存器；32 位类型（int32/uint32/float）需要 2 个，高字在前
- 系数：原始值 × 系数 = 显示值，`0.1` 显示 1 位小数
- 以 `#` 开头的行会被忽略
- **CSV 和 TXT 都行**：解析时按行自动判断分隔符——有 Tab 用 Tab，有逗号用逗号，
  有分号用分号，都没有就按连续空白切。所以 Excel 另存的 txt、记事本手打的表都能直接导入。
  导出时选 `.txt` 就写成 Tab 分隔（比逗号更对齐，Excel 也能直接打开）。

## CAN（USB-CAN）

用的是厂商的 `ControlCAN.dll`（创芯科技 VCI 接口，兼容致远/周立功老版本）。

**必须编成 32 位**：厂商只提供 32 位 DLL，64 位进程加载不了它。
Release 里发布的就是 32 位版本。

**两个前置条件（缺一个都打不开设备，且都不会报错、只会返回 0）：**

1. **驱动要装**。设备是 `USB\VID_0471&PID_1200`，驱动包在 GitHub Release 下载
   （`usbcan_driver.zip`），解压后安装：

   ```powershell
   pnputil /add-driver <解压路径>\USBCAN.INF /install
   ```

   装好后设备管理器里显示 `ZLG USBCAN`，状态应为 OK。

2. **`kerneldlls` 目录要和 exe 放一起**。`ControlCAN.dll` 会去加载
   `kerneldlls\usbcan.dll`，只拷一个 `ControlCAN.dll` 出来是打不开设备的
   （现象：`VCI_OpenDevice` 恒返回 0）。

命令行直连（不用手点）：

```bash
BusScope.exe --can 4:0:500000                 # DevType:通道:波特率
BusScope.exe points.csv --modbus COM3:115200 --poll
                                              # 加载点表 + 开串口 + 立即轮询
```

界面参数：

| 项 | 说明 |
|---|---|
| 设备类型 | `USB-CAN II` = DevType 4，`USB-CAN I` = DevType 3，`CANalyst-II` = 21；打不开就换一个试 |
| 通道 | 盒子上的 CAN1 / CAN2 |
| 波特率 | 1000k ~ 10k，走 16 MHz 标准分频表 |

打开成功时标题栏右侧会显示读到的板卡型号、序列号和通道数（来自 `VCI_ReadBoardInfo`），
可以用来确认连的是哪块卡。


## 构建

> ⚠️ 工程路径不要包含中文或空格。命令行 qmake 在中文路径下会生成 `????` 路径而链接失败；
> 建议把仓库放在 `D:\dev\busscope` 这类纯英文路径，或直接用 Qt Creator 打开。

Qt Creator：打开 `busscope.pro` → 选择套件 → 构建。

**用哪个套件取决于要不要 CAN：**

| 套件 | 适用 | 说明 |
|---|---|---|
| `Qt 5.14.2 MinGW 64-bit` | 只用 Modbus | 打包体积稍大，CAN 用不了（厂商 DLL 是 32 位） |
| `Qt 5.14.2 MinGW 32-bit` | Modbus + CAN | **Release 里发布的就是这个版本** |

命令行（32 位，与发布版一致）：

```bash
set PATH=E:\qt5\5.14.2\mingw73_32\bin;E:\qt5\Tools\mingw730_32\bin;%PATH%
mkdir build && cd build
qmake ..\busscope.pro
mingw32-make -j4
```

产物在 `bin/BusScope.exe`，运行时需要 Qt 的 `bin` 目录在 PATH 中；
分发时把 Qt5Core/Gui/Widgets/SerialPort、`platforms\qwindows.dll`、MinGW 运行库
和 `ControlCAN.dll` 一起拷到 exe 旁边即可（Release 提供的压缩包就是这种自包含状态）。

## 目录职责

```
busscope.pro          qmake 工程（唯一构建入口）
src/main.cpp          程序入口：高 DPI、主题、主窗口、命令行点表
src/app/              界面层：main_window 只做框架与跨页接线；slave_page / poll_page / can_page 各自持有控件与槽函数；theme 提供设计令牌 + QSS
src/core/             与 UI 无关的数据层：Frame / PollTask 结构、两个 QAbstractTableModel、点表文件读写（point_file）
src/io/               设备链路层：ModbusLink（串口收发、切帧、超时）、PollEngine（轮询调度）
src/proto/modbus/     纯协议实现：CRC16、帧解码、点表映射（可单独单测）
res/theme/dark.qss    深色主题样式表，颜色与 src/app/theme.h 保持一致
examples/             示例点表与配置样例，只放数据文件，不放代码
docs/                 说明文档（串口调试工具手册）
```

分层约定：`proto` 不依赖 Qt Widgets，`core` 不依赖 `io`，`app` 只做装配。

## 与开源原型的关系

实现参考了以下开源项目的思路，未直接复制代码：

- [SantaJiang/ModbusDebuger](https://github.com/SantaJiang/ModbusDebuger)（GPL-3.0）：周期发送、串口刷新、HEX/ASCII 切换、日志保存的交互形式。
- [x-tools-author/x-tools](https://github.com/x-tools-author/x-tools)（LGPL-3.0）：多协议调试器的整体信息架构。
- [Serial-Studio](https://github.com/Serial-Studio/Serial-Studio)：帧列表 + 详情面板的分栏方式。

本工程自身代码未引入上述项目的源码，因此不继承其许可证。
